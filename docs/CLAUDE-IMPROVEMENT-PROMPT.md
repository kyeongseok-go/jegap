목표는 장식이 많은 사이트가 아니라, 일반인이 자기 지출을 확인하고 다음 행동까지 할 수 있는 신뢰할 만한 서비스다. JEGAP 이름, 사용자가 선택한 영수증 디자인·종이 질감·색감은 유지하면서 완성도를 높여. 실제 사용자 평가 없이 95점 같은 자체 점수를 완료 근거로 쓰지 마.

## 1. 먼저 데이터와 표현을 바로잡아

- 학원은 과목 키워드만 같다고 동일 상품으로 비교하지 마. 원래 과정명·학년·과목·시간·횟수·기간·구성을 보존하고 실제 수집 가능한 조건을 확인해. 음악/체육처럼 다른 과정을 합친 코드를 분리해. 조건 확인 불가 항목은 공시가격 참고로 표시하고 배수·백분위·고가 하이라이트에서 제외해. 부족한 정보를 AI로 추정하지 마.
- 장례는 품명뿐 아니라 규격·단위·기간·포함 서비스를 유지해. 특실/일반실, 1개/묶음, 1시간/1일 등의 혼합 비교를 차단해. 과거 데이터를 현재 가격처럼 표시하지 마. 원 자료 복원이 불가능하면 비교 수치를 감추고 최신 가격 확인 목록은 계속 제공해.
- 관리비의 장충금 지표는 ㎡당 월 부과액임을 명확히 해. 누적 잔액·필요 공사비가 확인되지 않으면 재원 부족이나 미래 목돈 부담을 진단하지 마. 추가로 확인할 질문으로 바꿔.
- mid-rank 백분위를 실제 개수로 번역하지 마. 유효 표본에서 자기보다 높은 단지 K와 전체 N을 직접 계산하거나 중간값·차액을 보여줘. 0원 제외 후 표본 수를 화면·차트·설명에서 일치시켜. 동률/최소/최대 케이스를 테스트해.
- 관리비 총액·난방비·장충금의 제목, 차트, 단위를 분리해. 산식이 다루지 않는 사실을 헤드라인으로 약속하지 마.
- 조건 미확인·오래된 데이터는 실명 고가 하이라이트에서 제외해. 실명 유지라는 기존 사용자 결정을 존중하되 비교 타당성은 반드시 확보해. 법률 위반·과다청구 여부를 통계만으로 판단하지 마.

## 2. 첫 화면과 문구를 바꿔

각 카테고리 첫 화면을 `내 상황을 설명하는 제목 → 얻는 결과 두 문장 → 검색/지역 선택 → 실제 결과 미리보기 → 가능한 다음 행동` 순서로 구성해. 장식 때문에 검색을 아래로 밀지 마. 예시는 실제 데이터와 기준일을 표시하고 예시임을 명확히 해.

제목 방향:
- 관리비: “우리 아파트 관리비, 어떻게 달라졌을까요?”
- 병원비: “진료받기 전, 비급여 가격부터 확인하세요”
- 학원비: “학원비, 등록 전에 확인하세요”
- 장례비: “장례 비용, 항목별로 확인하세요”
- 생활물가: “우리 지역 냉면값, 얼마나 올랐을까요?”

기능을 확인한 뒤 더 정확하고 자연스럽게 다듬어도 된다. “검진표가 압니다”, “유일한 방어”, “아는 사람만”, “부르는 게 값” 같은 과장·대립 표현은 제거해. CTA는 “가격 확인하기”, “우리 단지 확인하기”, “상담 때 물어볼 내용 만들기”처럼 행동과 결과를 말해.

병원 검색 범위가 병원급 이상이라면 의원급 미포함을 검색 옆에 밝혀. 같은 시도 비교를 “우리 동네”라고 쓰지 마. 장례 데이터가 2023년6월이면 제목 근처·상세·공유에 기준일을 표시해. 생활물가 지역 선택을 추세 카드 위로 옮기고 식재료와 외식 가격의 차이로 마진을 추론하지 마.

## 3. 모바일·상세·행동 흐름을 개선해

- 360/390/768/1280px에서 헤더·검색·활성 탭이 잘리지 않게 해. 상세 검색은 필요한 경우 별도 행에 두고 단순 overflow hidden으로 문제를 숨기지 마. 모든 탭을 발견할 수 있게 해.
- 모바일 표에서 중간값·표본 수를 숨기지 마. 카드형 행으로 가격, 단위, 비교값, 비교 지역, 표본 수, 기준일을 유지해. “상위1%”는 가격이 높은 쪽이라는 방향을 명확히 해.
- 상위20항목만 보여주는 현재 구조에 전체보기와 항목찾기를 추가해. 가격 차이가 큰 항목이 항상 사용자가 원하는 항목은 아니다.
- 세 카테고리 상세 기관명은 h1으로 표시해. 입력 글자는 모바일16px 이상, 터치 영역·키보드·포커스·reduced-motion을 점검해. 모바일의 영수증은 작고 가벼운 비주얼로 검토하되 주요 정보를 밀지 마.
- 검색은 로딩/없음/서버 오류를 구분하고 재시도를 제공해. 새 검색어에 이전 결과가 제출되지 않게 해. 한글 조합 입력과 Enter 선택도 검증해.
- 문서 생성은 로딩/완료/중단/오류/429를 구분하고 복사 성공·실패를 알려줘. 완성되지 않은 문서를 완성본처럼 보증하지 마.
- 진료 전 질문, 학원 시간·횟수·별도비용 질문, 장례 단위·필수/선택·견적 질문을 해당 결과와 연결해. 생활물가는 지정 업소 정보의 기준일·주소·확인 경로를 보여주고 현재 최저가라고 보증하지 마.

## 4. 보안과 운영 안내를 실제 동작에 맞춰

- 현재 인메모리 IP 제한만으로 전역 과금을 막았다고 말하지 마. 운영자가 설정한 전체 사용 한도와 공유 제한 방안을 선택하고 trade-off를 기록해. 계정 설정이나 외부 자격 증명이 없으면 LLM 호출은 표준 템플릿으로 안전하게 대체하고 필요한 설정만 인계해. 제한 저장소 오류도 비싼 호출을 무제한 허용하면 안 된다.
- 비활성화 스위치, 업스트림 타임아웃, 요청 본문 크기 제한, 반복 요청 중복 억제를 구현해. 공개 데이터를 다루는 서비스이므로 로그인 강제는 추가하지 마.
- 숫자·법 조항·기관명·항목명은 서버에서 확정해서 조립하거나 출력 검증 후 공개해. system 프롬프트만으로 “그대로”를 보증하지 마. 잘못된 내용을 먼저 스트리밍하는 설계를 피하고 실패 시 검증된 표준 양식을 사용해.
- 개인정보 안내를 실제 보관·삭제 및 Vercel 로그·Claude 전달 항목과 일치시켜. 현재 Map은60초 뒤 자동 삭제되지 않는다. 호스팅 로그 보관 설정은 직접 확인 가능한 범위만 기록하고 추측하지 마.
- 정정 창구는 비로그인 외부 사용자로 접근 검증해. 현재 GitHub 링크가404면 사용자 소유의 확인된 연락 경로로 바꿔. 임의 연락처를 만들거나 저장소를 공개하지 마. 소유 연락처가 필요한 경우 다른 작업을 먼저 끝내고 그 부분만 인계해.
- 출처별 정확한 원문 URL·자료 기준일·이용허락 조건을 정리해. 모든 데이터가 같은 라이선스라고 일괄 선언하지 마. 법률 문구는 현행 공식 출처로 대조하고 확정할 수 없는 것은 명시해.
- CSP는 보고 모드 등으로 호환성을 검증하고, nosniff·Referrer-Policy·frame-ancestors 등 필요한 헤더를 적용해. 프레임워크·폰트·이미지를 깨뜨리지 마. API 키/환경변수 값을 출력·커밋하지 마.

## 5. 완료 조건과 결과 보고

먼저 우선순위와 변경 대상을 짧게 정리하고 바로 실행해. 독립 작업은 병렬화하되 같은 파일 충돌을 피하고 최종 통합 검토를 수행해. 제품 수정은 별도 브랜치에서 검토 가능한 커밋으로 남겨. 공개 배포·외부 서비스 설정 변경은 현재 세션의 사용자 권한 범위에 따라 처리해.

실패 사례를 포함한 의미 있는 테스트를 작성해: 비교 단위 불일치, 동률·유효 표본 수, 보호 필드 변경, 제한 초과/저장소 실패, 잘못된 입력, 검색 실패. 기존 테스트·타입 검사·빌드와 실제 브라우저 점검을 수행해. 테스트 통과가 데이터 비교의 타당성을 자동 증명한다고 쓰지 마.

다섯 홈과 각 상세의 데스크톱·모바일 캡처를 남겨. 화면 밖 넘침, 숨겨진 비교 근거, 깨진 문의 링크가 없어야 한다. 실제 사용자 확인은 사람을 모집할 수 있을 때 진행하고, 못 했다면 미실시라고 표시해.

최종 보고는 수정 전후 문구 표, 디자인 전후 화면, 데이터 비교 가능/불가 기준, 보안 검증 결과, 남은 사용자 설정을 포함해. “최고 퀄리티 완료” 같은 자기평가 대신 무엇이 달라졌고 무엇이 검증됐는지 근거로 보고해.
