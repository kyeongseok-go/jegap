# JEGAP 사용자 관점·디자인·보안 검토

검토일: 2026-09-17. 배포 사이트 https://jegap-one.vercel.app 및 로컬 HEAD `fbe4373`을 검토했다. globals.css와 apt-v2 이미지 등에 기존 미커밋 변경이 있어 보존했다. 이번 작업에서는 제품 코드를 수정하거나 배포하지 않았다.

## 결론

영수증·지면·JEGAP 브랜딩은 유지할 가치가 있다. 그러나 지금의 병목은 장식의 부족보다 **약속과 결과의 일치, 비교 조건의 타당성, 모바일에서 근거를 읽고 행동할 수 있는가**이다. 실제 사용자 테스트 없이 사용률·전환율이나 심사 점수를 확정할 수 없다. 기존 자체 95점 평가는 이번 검토의 근거로 사용하지 않았다.

## 검토 범위와 한계

- 배포된 다섯 홈의 문구를 확인하고 데스크톱 홈·병원 화면, 390×844 학원·장례·생활물가 및 장례 상세 화면을 직접 확인했다.
- 가격 산식·인제스트·검색·대필·제한 로직·개인정보 설명을 읽었다.
- 비로그인 문의 URL은 GitHub 404로 재현됐다.
- npm audit --omit=dev 결과 알려진 운영 의존성 취약점 0건. 이것은 서비스 전체 보안 인증이 아니다.
- 프로덕션 과금 API 반복 호출, 침투·부하 시험은 하지 않았다. Vercel 계정별 로그·방화벽·예산 설정은 확인하지 않았다. 전체 데이터 원본 재대조와 법률 적법성 확정은 범위 밖이다.

## 우선순위별 발견

### P0: 공개 비교의 신뢰와 운영 보호

1. **학원·장례의 비교 단위가 보존되지 않는다.** `app/scripts/ingest_neis.py:36`은 키워드로 과목을 합치며 피아노·바이올린을 음악, 태권도·수영을 체육으로 묶는다. `:89`에서 원래 과정명 대신 표준 코드와 중앙값을 저장한다. 시간·횟수·정원은 비교에 없다. `app/scripts/ingest_funeral.py:40`은 세부내용을 버리고 품명만 키로 사용한다. 단위·기간·구성 차이가 배수에 섞일 수 있다. 주석·하단 면책으로 해결되지 않는다. 비교 가능성이 확인된 항목만 배수·순위를 내고 나머지는 원 공시 가격과 확인할 조건을 보여줘야 한다.

2. **월 부과 수준을 수선 재원 충분성으로 읽게 한다.** `app/scripts/ingest.py:92`, `app/lib/data/kapt.ts:25`의 rv는 ㎡당 월 부과액이다. 총 잔액·계획 공사비·최근 집행액을 이용한 재원 부족 검증이 아니다. 그런데 `app/components/CheckupView.tsx:138`과 `app/lib/engine/opinion.ts:27`은 미래 목돈 부담으로 연결한다. 월 부과액이 낮다는 사실과 재원 부족이라는 추론을 분리해야 한다. 실제 공시 잔액·계획 근거가 없으면 후자를 확정하지 않는다.

3. **백분위를 정확한 단지 개수로 바꾸는 문구 오류.** `CheckupView.tsx:51`은 mid-rank 백분위를 반전·클램프해 “100곳 중 91곳이 더 많이”로 표시한다. 동률이 있으면 백분위 보수는 엄밀한 초과 비율이 아니다. `checkup.ts:12`는 0원 표본을 제외하면서 `:41`의 peerCount는 전체 유사군 수라 실제 유효 비교 개수도 다를 수 있다. 유효 표본 N과 엄밀하게 높은 단지 K를 직접 계산해 “비교 가능한 N곳 중 K곳보다 월 부과액이 낮습니다”로 표시하거나 단순히 원화 중간값과 차액을 쓴다.

4. **AI 과금 제한은 전역 제한이 아니다.** `app/lib/pricedom/ratelimit.ts:6`의 Map은 서버 인스턴스별이다. 확장·재시작·다수 IP에 걸친 예산 상한을 보장하지 않는다. 공유 제한 또는 검증된 플랫폼 방어, 운영자가 설정하는 전역 사용 한도, LLM 비활성화 스위치와 표준 양식 폴백이 필요하다. IP 위조가 재현된 것은 아니다. Vercel 공식 문서는 X-Forwarded-For를 덮어쓴다고 설명한다.

5. **법 조항·숫자 불변은 프롬프트 지시일 뿐이다.** `app/lib/pricedom/polish.ts:10`은 모델에 변경 금지를 요청하지만 결과 검증은 없다. `app/components/RxSimple.tsx`는 “그대로 가져왔습니다”를 보증한다. 수치·항목·조항은 결정론적으로 조립하고, 모델이 다듬을 범위를 제한하거나 검증 통과 후 출력해야 한다. 틀린 숫자를 일단 스트리밍한 뒤 교체하는 것은 해결이 아니다.

### P1: 바로 체감하는 사용성·문구

6. **모바일 헤더가 넘친다.** 장례 상세 `/f/광명성애병원장례식장`, 390px에서 document scrollWidth=622px, 검색 wrapper 폭=0, x=362. `globals.css:27,35,187`의 한 줄 flex와 검색 min-width 조합. 탭은 221px 영역 안에 291px 콘텐츠가 있고 현재 생활물가 탭도 잘린다. 검색을 별도 행으로 배치하고 활성 탭을 항상 보이게 한다.

7. **모바일에서 비교 근거를 숨긴다.** `globals.css:238`은 3번째 열(중간값·표본 수)을 display:none 처리한다. 사용자는 “10배”만 보고 기준 금액을 못 본다. 카드식 행으로 바꾸되 가격·단위·중간값·지역·표본·기준일은 유지한다.

8. **홈의 약속과 첫 결과가 다르다.** “나만 많이 내는 걸까?” 다음에 나오는 큰 숫자는 관리비가 아닌 장충금 부과액이다. 같은 페이지에서 관리비 흐름 차트 설명과 난방비 상승 신호도 섞인다. 관리비·난방비·장충금을 각 지표명으로 분리하고 첫 결과가 헤드라인에 답하도록 한다.

9. **병원 범위와 지역 표현이 과도하다.** `app/lib/medical/hira.ts`는 병원급 이상 자료를 쓰고 비교는 같은 시도×종별이다. `/h`의 “전체 의료기관”, “우리 동네”, 의원처럼 보이는 검색 예시는 사용자의 기대와 어긋난다. 검색 바로 옆에 실제 포함 범위·미포함 범위를 알려야 한다.

10. **장례 카피가 불안을 키운다.** “정신없을 때”, “유일한 방어”보다 “장례 비용, 항목별로 확인하세요”가 상황에 맞다. 2023년 6월 자료는 현재 가격 판단이 아닌 과거 공시 참고자료로 첫 화면·결과·공유에서 명확히 표시한다. “이번 주 발견”이 가격 최신성을 암시하지 않도록 발견일과 공시일을 분리한다.

11. **생활물가의 핵심 행동이 늦다.** 390px에서 지역 선택은 약720px 지점 이후에 시작한다. 먼저 지역을 선택하게 하고 추세 카드는 아래로 보낸다. +7% 대 +6%만 있는 카드에 “같이 움직이지 않습니다”라는 큰 결론은 과하다. “외식 가격과 식재료 가격의 변화”로 고치고 원가·마진 분석이 아님을 설명한다.

12. **상세 결과가 가격 차이 큰 순 20개만 보여준다.** `PriceCheckup.tsx:57,69`에 더보기 제어가 없다. 목적 항목 검색·전체 보기·필요 항목 중심 정렬이 필요하다. “상위1%”는 우수함으로 오독할 수 있어 “가격이 높은 쪽” 등 방향을 밝힌다.

13. **오류·진행 상태와 복사 피드백이 약하다.** Search/PriceSearch의 실패 catch는 무응답이다. loading/error/empty를 분리한다. 검색어 변경 중 이전 결과를 제출하지 않도록 막는다. RxSimple은 복사 성공·실패를 알리지 않으며 네트워크 실패가 중단과 같은 경로다. 429 재시도 시점을 알리고 생성·중단·오류를 구분한다.

14. **문의 창구가 실제로 작동하지 않는다.** `app/lib/site.ts`의 GitHub Issues는 비로그인 404. 공개 접근 가능한 문의 창구가 필요하다. 임의로 저장소를 공개하거나 연락처를 만들어서는 안 된다. 실제 운영 가능한 응답 기한으로 “24시간 처리” 약속도 재검토한다.

### P1: 사실에 맞는 운영 안내

15. `app/app/terms/page.tsx:32`의 “60초 뒤 사라집니다”는 Map에 삭제 타이머가 없는 구현과 다르다. IP별 제한은 사람별 제한도 아니다. 애플리케이션의 별도 DB 미저장과 호스팅 제공자의 로그 처리를 분리해 실제 설정 확인 후 안내한다.
16. `terms/page.tsx:57`의 모든 자료 공공누리1유형 주장은 출처별 이용조건 확인표가 필요하다. 이번 검토에서 위법이라고 판정한 것은 아니다. 근거 없는 일괄 보증을 피하라는 발견이다.
17. 홈 HEAD 응답에서 HSTS는 확인했지만 CSP·X-Content-Type-Options·Referrer-Policy는 보이지 않았다. 관련 프레임워크·폰트·이미지와 호환되는 정책을 테스트 후 도입한다. CSP 부재 자체를 XSS 재현으로 표현하지 않는다.

### P2: 시각적 완성도

- 영수증·종이색·빨간 강조의 일관성은 유지. 큰 제목, 짧은 설명, 검색, 1개 실제 결과 미리보기 순으로 단순화한다.
- 모바일에서 3D 영수증은 숨겨지므로 데스크톱 장식에만 투자하면 실제 모바일 인상은 개선되지 않는다. 가벼운 작은 정지 비주얼 또는 지면 디테일을 사용하되 CTA를 밀지 않는다.
- 보조 설명이 작고 반복이 많다. 원칙·법적 근거는 필요할 때 펼치도록 하고 핵심 제한·기준일은 숫자 옆에 남긴다.
- `PriceCheckup.tsx:36`: 상세페이지 h1 없이 h2부터 시작. 기관명 h1 권장.
- `globals.css:422`: 모바일 입력15px. iOS 실기기에서 확대 여부 확인 후16px 이상 유지.
- HeroReceipt의 “얼마가 제값인지는 검진표가 압니다”는 적정가 판단 능력을 과장. “공개된 가격을 한눈에” 권장.
- `globals.css:44`: 무한 pulse는 정지 또는 유한 애니메이션으로. reduced-motion 지원만으로 일반 사용자 반복 움직임 문제까지 해결되는 것은 아니다.
