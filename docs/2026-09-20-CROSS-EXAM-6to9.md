당신은 데이터 제품의 **적대적 검증가**다. 아래 서비스가 사용자에게 **틀린 숫자를 보여줄 경로**를
찾는 것이 당신의 일이다. 잘 만들었다는 평가는 필요 없다. 반례와 실패 경로만 내라.

## 서비스 개요

정부 공개 데이터로 "내가 내는 값이 어디쯤인지"를 보여주는 무료 웹 서비스다.
판정하지 않고 **위치(백분위)와 배수**라는 사실만 제시한다. 로그인 없다.
기존 5개 도메인(아파트 관리비·병원 비급여·학원 교습비·장례비·지방물가)에
**3개를 새로 붙였다.** 이 3개를 검증해 달라.

공통 엔진은 하나다. `기관 × 항목 × 가격` 을 받아,
① 같은 유사군에서 표본이 30곳(주유소는 10곳) 이상이면 비교하고
② 모자라면 한 단계 넓히며 그 사실을 화면에 표기하고
③ 그래도 모자라면 **순위를 내지 않고 금액만** 보여주며
④ 중간값이 1,000원 미만이거나 배수가 50배 초과·1/50 미만이면 아예 표시하지 않는다.
자기 자신은 표본에서 제외한다. 동률은 mid-rank 로 처리한다.

## 검증 대상 1 — 창업비용편 (공정거래위원회 가맹사업 정보공개)

- 기관 = 브랜드(11,360곳), 항목 = 가맹금·교육비·보증금·기타비용·합계
- 유사군 = **같은 업종중분류**(한식·치킨·커피 등 44종) → 30곳 미만이면 업종대분류
- 금액 단위가 API 명세에 없다. 샘플이 `합계 38500` 이고 천원 단위로 보여 ×1000 을 가정했다.
  근거: 그렇게 해석하면 합계 중앙값 7,980만원, 교촌치킨 가맹금 676만원·합계 1억 3,100만원이
  되어 실제 공시와 맞는다. **이 추론이 안전한가?**
- **기타비용은 순위를 내지 않는다** — 포함 범위가 브랜드마다 다르기 때문(인테리어·장비·시설).
- **합계는 네 항목을 모두 공시한 브랜드끼리만 비교한다** — 전체의 26%가 일부만 공시하는데,
  그 합계는 전체 창업비용이 아니기 때문.
- 그래도 같은 업종 안에 예식장 45.8억, 대형 카페 37억 같은 값이 남는다(실제 공시값 확인함).

## 검증 대상 2 — 주유소편 (한국석유공사 오피넷)

- 기관 = **시군구**(230곳), 항목 = 유종 4종(휘발유·경유·고급휘발유·실내등유)
- 값은 그 시군구의 **평균 판매가격**이다. 개별 주유소가 아니다.
  이유: 개별 주유소를 주는 공개 API 는 "지역별 최저가 Top20" 뿐이라 표본이 최저가로 편향된다.
  반경 검색은 전수지만 TM 좌표 격자가 필요해 일 300콜 한도로 전국을 못 덮는다.
- 유사군 = 같은 시도의 다른 시군구(10곳 이상) → 미달이면 전국
- 오피넷은 **전남과 광주를 한 지역으로 묶어** 조사한다. 그대로 따랐다.
- 실측 배수 범위 0.92 ~ 1.1배.

## 검증 대상 3 — 생필품편 (한국소비자원 참가격)

- 기관 = 점포(447곳), 항목 = 상품(604종)
- 유사군 = **같은 상품 · 같은 업태**의 점포 → 같은 시군구 30곳 미만이면 시도 → 전국
- 업태 코드(LM/SM/DP/CS)의 **뜻을 확인하지 못했다.** 코드표 API 의 classCode 유효값이
  명세에 없고 price.go.kr 은 응답하지 않았다. 뜻을 모른 채 **같은 코드끼리만 비교**하도록
  코드에 업태를 붙였다. 화면에는 업태를 표시하지 않는다.
  (분리가 필요했던 근거: 진라면 5개입이 LM·SM 3,950원인데 CS 는 5,000원이다.)
- **할인 중이거나 1+1 인 가격은 순위를 내지 않는다**(평상시 단가가 아니므로).
- 주소의 시도 표기가 31종으로 제각각이어서("서울" / "서울특별시") 16개로 정규화했다.
- 조사 주기가 문서는 '매주 금요일'인데 실제는 격주다. 최근 금요일부터 역산해 유효 조사일을 찾는다.

## 답해야 할 것

각 항목에 대해 **구체적 반례나 실패 경로**를 제시하라. "주의가 필요하다" 같은 말은 답이 아니다.

1. **비교 단위 오염** — 위 세 도메인에서, 조건이 다른 값이 한 표본에 섞여 배수가 틀리는
   경로가 아직 남아 있는가? 어떤 입력에서 그렇게 되는가?
2. **단위 오류** — 창업비용의 ×1000 가정이 틀릴 수 있는 시나리오가 있는가?
   합계 중앙값이 1천만~3억원 밖이면 파일을 쓰지 않는 게이트를 걸었는데, 이 게이트를
   통과하면서도 단위가 틀릴 수 있는 경우는?
3. **평균의 평균** — 주유소편은 "시군구 평균"들을 다시 중간값·백분위로 처리한다.
   이것이 사용자를 오도하는 구체적 상황을 제시하라.
4. **업태를 모른 채 쓰는 것** — 생필품편이 업태 코드의 뜻을 모르면서 비교 키로만 쓰는 설계에
   구멍이 있는가? 코드가 재배정되거나 신규 코드가 생기면 어떻게 되는가?
5. **표본 게이트 우회** — 30곳 기준·완화 사다리·50배 상한을 **우회해 이상값이 화면에 뜨는**
   입력이 있는가? 경계값을 구체적으로 들어라.
6. **법·라이선스** — 오피넷 저작권정책은 수익 목적 이용 시 사전 협의를 요구한다.
   현재 비영리·무광고로 운영하며 `/terms` 에 명시했다. 이 대응이 충분한가? 부족하다면 무엇이?
7. **화면 문구와 실제 동작의 불일치** — 위 설명 중 "이렇게 하면 사용자가 다르게 이해할 것"인
   지점을 짚어라.

마지막에 **가장 먼저 고쳐야 할 것 3개**를 심각도 순으로 줄 세워라.
