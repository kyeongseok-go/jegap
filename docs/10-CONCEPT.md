## 1. 기획 — 서비스 기획

### MVP 정의
> 반복업무의 **결과물 파일 한 개**를 올리면, AI가 그걸 만들기까지의 작업 과정을 역추론해서, **연간 시간 비용과 실질 시급**을 계산하고, 그 업무를 대신할 **에이전트 명세를 생성**한다.

MVP에 들어가는 것 딱 네 개:
1. 파일 업로드 → 산출물 역추론 (단계 분해)
2. 단계별 소요시간 추정 → 주/연 환산 → 실질 시급
3. 자동화 가능성 등급 + 대체 에이전트 명세 생성
4. 결과 공유 카드 (무로그인, URL 하나)

MVP에서 뺀 것: 로그인, 결제, 팀 기능, 실제 업무 시스템 연동, 에이전트 상시 실행. — 없어도 가치가 증명되고, 있으면 9일이 무너진다.

### 타겟 유저
- **1차**: 매주 같은 형태의 문서·시트·메일을 만드는 실무자 (주간보고, 정산, 실적 취합, 고객 응대 템플릿)
- **2차(수익원)**: 그 실무자들의 팀장·조직장. "우리 팀이 반복업무에 연 몇 시간을 쓰는가"를 알고 싶어 하는 사람
- **비타겟**: 이미 자동화를 직접 짤 수 있는 개발자. 이들은 도구가 아니라 근거만 필요하다

### 핵심 기능
| 기능 | 설명 | AI 역할 |
|---|---|---|
| 산출물 역추론 | 파일 → "이걸 만들려면 거쳤어야 할 단계" 재구성 | **LLM 고유**. 문서 구조·데이터 출처·수작업 흔적에서 프로세스 추론 |
| 시간 비용 환산 | 단계별 분 → 주기 × 연간 → 실질 시급 | 추정은 LLM, 계산은 코드 |
| 자동화 등급 | 단계별 (완전자동 / 반자동 / 사람필수) 판정 | LLM 판단 |
| 대체 에이전트 생성 | 같은 산출물을 만드는 실행 명세 + 샘플 1회 실행 | LLM 생성 + 툴 실행 |
| 공유 카드 | OG 이미지 달린 결과 페이지 | — |

### 경쟁 서비스 분석
| 구분 | 대표 | 접근 | 빈 곳 |
|---|---|---|---|
| 워크플로우 빌더 | Zapier AI, n8n, Make, Dify | "무엇을 자동화할지 이미 아는 사람"이 조립 | **왜 자동화해야 하는지를 증명해주지 않음** |
| 프로세스 캡처 | Tango, Scribe, Guidde | 화면을 녹화해 매뉴얼 생성 | 확장프로그램 설치 필요, 시간 비용 미산출 |
| 타임 트래커 | Toggl, RescueTime, Clockify | 시간을 기록 | 기록 마찰이 크고, 기록해도 **해결로 이어지지 않음** |
| 프로세스 마이닝 | Celonis, UiPath Process Mining | 로그에서 프로세스 발견 | 엔터프라이즈 전용, 도입에 수개월 |

**빈 곳**: 증거 기반으로 "이 반복업무가 당신에게 연 몇 시간, 시급 얼마"를 즉시 계산하고 곧바로 해결까지 잇는 **개인용 진단 도구**가 없다.

### 차별화 전략 (한 문장씩)
1. **진단이 앞단에 있다.** 경쟁 도구는 전부 "만들기"부터 시작한다. 우리는 "왜 만들어야 하는가"를 숫자로 먼저 증명한다.
2. **자기보고를 받지 않는다.** "주 4시간 걸려요"를 믿지 않고 산출물 실물에서 역추론한다. 이게 기술적 해자이자 신뢰의 근거.
3. **설치가 없다.** 파일 하나, 30초, 로그인 없음.
4. **광고로 돈을 벌지 않는다.** 시간을 돌려주는 서비스가 시간을 뺏는 수익모델을 쓰면 자기모순이다. 명시적으로 배제한다.

### 데모 서사 (3분 발표 골격)
1. **[0:00]** 1,022만 명이 3.8개 앱을 돌려 월 2만 원을 번다. 하루 30~40분 → **실질 시급 500~1,000원.** 최저임금의 1/10.
2. **[0:30]** 그런데 이건 앱테크만의 문제가 아니다. 당신의 주간보고도 값이 매겨진 적이 없다. **돈에는 가계부가 있는데 시간에는 없다.**
3. **[1:00]** 라이브 데모 — 심사위원의 실제 파일을 받아 업로드. 역추론 과정이 실시간으로 흐른다.
4. **[2:00]** 결과: 단계 7개, 회당 52분, 주 1회, **연 45시간, 실질 시급 8,400원.** 이 중 5단계가 완전 자동화 가능.
5. **[2:30]** 대체 에이전트 생성 → 샘플 실행 → 같은 산출물이 나온다. **연 45시간 중 38시간 회수.**
6. **[2:50]** 개인에서 팀으로. 확장 스토리.

## 2. 설계

### 화면 설계 (5개, 그 이상은 D-8에 사치)
| # | 화면 | 핵심 |
|---|---|---|
| S1 | 랜딩 | 드롭존 하나. + 프리셋 3개(주간보고/정산시트/반복메일)로 **파일 없이도 30초 체험** |
| S2 | 분석중 | 역추론 단계를 SSE로 스트리밍. *이 화면이 데모 임팩트의 절반* |
| S3 | 결과 | 단계 타임라인 · 시간 환산 · 실질 시급 · 자동화 등급 |
| S4 | 에이전트 | 대체 에이전트 명세 + 샘플 실행 결과 diff |
| S5 | 공유 | OG 이미지 붙은 정적 결과 페이지 |

**설계 원칙**: S1→S3까지 클릭 2회, 30초 이내. 심사위원 이탈률이 예선 점수다.

### 사용자 시나리오
> 마케팅팀 3년차 지민(가명)은 매주 월요일 오전, 5개 채널 실적을 시트에서 긁어 주간보고 슬라이드를 만든다. 늘 한 시간쯤 걸린다고 막연히 생각한다.
> 랜딩에 지난주 보고서를 드래그한다. 30초 뒤 화면: 7단계, 회당 52분, **연 45시간 — 근무일 5.6일.** 실질 시급 8,400원.
> "5단계가 완전 자동화 가능"을 누른다. 에이전트 명세가 뜨고, 샘플 실행 결과가 지난주 보고서와 나란히 표시된다.
> 결과 카드를 팀 슬랙에 붙인다. 팀장이 묻는다. "우리 팀 전체로 돌리면?"

### 데이터 모델 (ERD)
로그인이 없으므로 users 테이블 없음. 4개 테이블로 끝.

```
analysis (분석 1건)
  id (uuid, pk) · created_at · source_type(file|preset)
  file_name · file_kind(xlsx|docx|pdf|csv|eml) · file_bytes
  status(queued|running|done|failed) · error
  cadence(주1회 등) · total_minutes · annual_hours · effective_wage
  ↓ 1:N
step (역추론된 작업 단계)
  id · analysis_id(fk) · seq · title · description
  minutes · automatable(full|partial|human) · reason · suggested_tool
  ↓
agent (대체 에이전트)
  id · analysis_id(fk) · spec_json · sample_input · sample_output · created_at

share (공유 카드)
  slug (pk, 짧고 추측 불가) · analysis_id(fk) · og_image_url · view_count
```

원본 파일은 **저장하지 않는다.** 파싱된 텍스트만 분석에 쓰고 폐기. 개인정보·기밀 우려를 구조로 차단 — 요강도 과제에 타인 개인정보·기밀 포함을 금지한다.

### API 설계
| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | `/api/analyze` | multipart 업로드 또는 `{presetId}`. → `{analysisId}` |
| GET | `/api/analyze/:id/stream` | SSE. 역추론 진행 단계를 실시간 푸시 |
| GET | `/api/analysis/:id` | 결과 전체 |
| POST | `/api/analysis/:id/agent` | 대체 에이전트 생성 |
| POST | `/api/agent/:id/run` | 샘플 1회 실행 |
| POST | `/api/analysis/:id/share` | 공유 slug 발급 + OG 이미지 생성 |
| GET | `/s/:slug` | 공유 페이지 (SSR) |

## 3. 개발

### 기술 스택 — ponytail 사다리 적용
| 층 | 선택 | 이유 / 뺀 것 |
|---|---|---|
| 프레임워크 | **Next.js (App Router)** | 프론트+백엔드 한 저장소. **별도 백엔드 서버를 뺌** |
| 호스팅 | **Vercel** | git push = 배포. **Docker·k8s·CI 구성 전부 뺌** |
| DB | **Supabase Postgres** (무료) | SQL 그대로. **ORM 최소화**, 스키마 4테이블 |
| LLM | **Claude (claude-opus-5 / sonnet-5)** | 역추론=opus, 단순 분류=sonnet으로 비용 분리 |
| 파일 파싱 | `xlsx`, `mammoth`(docx), `pdf-parse` | **파서 직접 구현 안 함** |
| OG 이미지 | `@vercel/og` | **이미지 서버 안 세움** |
| 스타일 | Tailwind | |
| 인증 | **없음** | MVP에 불필요. 공유는 추측 불가 slug로 |
| 상태관리 | React 기본 + SSE | **Redux/Zustand 뺌** |

### 기초개발 → 서비스/웹
- **웹화면**: Next.js + Tailwind, 반응형. 심사위원이 모바일로 열 수 있다.
- **백엔드**: Next.js Route Handlers. CRUD는 Supabase 클라이언트 직결.
- **예외처리** (여기는 절대 게으르지 않는다):
  - 업로드 크기·확장자 화이트리스트 검증 (신뢰 경계)
  - 파싱 실패 → 사용자에게 원인 명시 + 프리셋으로 유도
  - LLM 응답 스키마 검증(zod). 실패 시 1회 재시도 후 부분 결과 표시
  - LLM 타임아웃·레이트리밋 → SSE로 상태 전달, 화면 멈춤 금지
  - **프롬프트 인젝션**: 업로드 파일 내용은 데이터로만 취급. 파일 안의 지시문을 따르지 않도록 시스템 프롬프트에 명시하고 출력은 구조화 스키마로만 수용
- **DB 구축**: `schema.sql` 한 파일. 마이그레이션 도구 도입 안 함(테이블 4개).

### 모바일
**React Native 안 한다.** 요강이 웹을 권장하고, 앱은 스토어 정식 출시가 필요해 9일 안에 불가능(심사 대기만 수일). **반응형 웹으로 대체.** — 이미지의 "모바일" 분기에서 우리가 택하는 쪽.

### 검증 (ponytail: 비자명 로직엔 실행 가능한 체크 하나)
`test_reverse.ts` 하나. 고정 샘플 파일 3개 → 역추론 결과가 (a) 스키마 통과, (b) 단계 수 3~12, (c) 합계 분이 0 초과인지 assert. 프레임워크·픽스처 없음.

## 4. 소스관리
- GitHub 단일 저장소, **private → 제출 후 판단**
- 브랜치: `main`(= 운영, Vercel Production) / `dev`(= Preview). 9일짜리에 git-flow는 과하다
- 커밋에 API 키 금지. `.env.local`만 사용, `.env.example` 커밋
- 요강 대응: 사용한 AI 툴을 `AI_TOOLS.md`에 기록하며 진행 → 제출서에 그대로 옮김 (**필수 기재 항목**)

## 5. 배포
- **Vercel** (`main` push → Production). Cloudflare는 불필요 — 한 겹 더 쌓을 이유가 없다
- 환경변수: `ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`
- Supabase 무료 티어. **주의**: 무료 프로젝트는 미사용 시 일시중지된다 → 심사기간 중 중단되면 실격. 9/21~10/17 동안 **외부 uptime 핑 5분 간격 필수**
- 비용 상한: Anthropic 콘솔에 예산 알림. 유료 API는 자비 부담이 요강 원칙

## 6. 출시
- **앱 등록 안 함** (웹 서비스). 요강의 스토어 요건을 회피하는 게 아니라, 애초에 웹이 맞는 형태
- 도메인: 커스텀 도메인 1개 + HTTPS (Vercel 자동). `*.vercel.app`도 심사에 문제없지만 도메인 하나가 완성도 신호
- 출시 체크리스트: OG 이미지 미리보기 확인(슬랙·카톡), 404/500 페이지, 모바일 실기기 확인, **심사기간 내내 접속 유지**

## 7. 유지보수 (= 품질 트랙 9/21~10/17)
- 장애 대응: Vercel 로그 + uptime 알림. 심사기간 중 다운 = 심사 제외 위험
- 기능 추가 우선순위: ① 역추론 정확도(프롬프트 개선, 이게 제품의 전부) ② 지원 파일 형식 확대 ③ 팀 단위 집계 ④ 로그인·저장
- 실사용자 피드백 루프: 결과 화면에 "이 단계 추정이 맞나요?" 한 줄 피드백 → 프롬프트 개선 근거

## 수익화 (VC 심사위원 대비)
- **광고: 배제.** 시간을 돌려주는 서비스가 시간을 뺏어 돈을 벌 수 없다. 이 배제 자체가 포지셔닝이다
- **B2C 구독**: 월 N회 초과 진단 + 이력 저장 (유입용, 본진 아님)
- **B2B (본진)**: 팀·조직 단위 반복노동 진단 리포트. 조직장이 "우리 팀 연 X시간"을 알면 예산이 움직인다. 좌석당 과금
- **확장 경로**: 개인 진단(무료·바이럴) → 팀 리포트(유료) → 진단 데이터가 쌓이면 **직무별 반복노동 벤치마크**가 되고, 이건 원티드의 채용·직무 데이터와 맞물린다 *(주최사 연결고리를 발표에서 한 줄로)*
