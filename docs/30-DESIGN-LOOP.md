## 루브릭 (7차원, 각 0~10)

1. **요강 정합** — 제출 요건(배포 링크·AI툴 기재·심사기간 가용성)·예선/본선 배점과의 정렬
2. **제품 설계 완결성** — 화면·플로우·엣지케이스·빈 데이터 상태까지 결정돼 있는가
3. **데이터·기술 설계** — API 실재성(추측 금지), 파이프라인, 스키마, 성능·비용 산정
4. **AI 설계** — 프롬프트 구조, 출력 검증, 모델 분리, 비용 상한, 인젝션 방어
5. **실행 계획** — 5일 일정의 시간 산정 현실성, 게이트, 폴백, 잘라낼 순서
6. **리스크·법** — 명예훼손·저작권·이용약관·다운타임, 각각 대응이 설계에 내장됐는가
7. **발표·데모 서사** — 3분 발표 시나리오, 라이브 데모 실패 대비, 투표 확산 경로

## 사이클 프로토콜

1. 설계 vN을 5인이 독립 채점 — 점수 + **치명 결함 top3** (결함 없으면 결함을 못 찾은 것)
2. 사실 불확실 항목은 채점 전 검증 (API 필드·약관·법리 — 추측 채점 금지)
3. 결함을 심각도순으로 수정 → v(N+1). 수정하지 않기로 한 결함은 사유 명기
4. 정직화 규칙: 과장 발견 시 표현 강등이 기능 추가보다 우선 (workmate "egress 봉쇄→축소" 선례)
