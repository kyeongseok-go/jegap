01목표 한 문장

Objective — 문서 전체를 한 줄로.

공공데이터 5원천의 가격 공시를 하나의 웹앱에 내장하고, 검색 한 번으로 "내가 내는 값이 유사 집단 어디쯤인지"를 위치·배수·사실 서술로만 보여준 뒤, 법이 보장하는 질문(열람·확인·반환)을 AI가 문서로 대필해 준다.

02배경

Background — 외부 맥락 없이 이 문서만으로 이해되도록.

한국에는 개인이 협상할 수 없는데 구조적으로 불투명한 가격이 있다. 아파트 관리비는 매달 청구되지만 옆 단지와 비교할 기준이 없고, 비급여 진료비·학원 교습비·장례식장 요금은 법이 공시를 강제하는데도 그 공시를 읽는 사람이 거의 없다. 정부는 이미 데이터를 열었다 — K-apt, 심평원, 나이스, e하늘, 행안부 지방물가. 문제는 데이터가 아니라 번역이다.

이 프로젝트는 원티드 AI Championship 2026 출품작으로 시작했다. 아이디어 10라운드 루프에서 "앱테크 광고 자동화"(실현 불가 판정), "관리비 단순 비교"(아파트아이 등 기존 서비스 존재로 강등)를 거쳐, "미래 리스크 판독 + 권리 기반 행동"으로 피벗했다. 이후 확장 계약(도메인 추상화)을 전제로 설계해, 실제로 5개 도메인이 하나의 공용 엔진 위에 올라갔다.

이 문서는 구현이 끝난 뒤 결정들을 역으로 기록한 것이다. 각 섹션의 포함 기준은 원칙 하나다 — "이 결정이 틀렸을 때의 비용이 큰가?" 되돌리기 쉬운 결정은 싣지 않았다.

04목표와 범위 제외

Goals / Non-goals — 목표는 구현이 아니라 영향으로 쓴다.

목표 (영향 중심)

  • 로그인 없이 클릭 1회 안에 첫 가치 — 심사위원이 30초 안에 판단을 끝낸다
  • 검진 결과가 공유 가능한 사실이 된다 (OG 카드 → 대중 투표 유입)
  • 조회에서 끝나지 않고 행동으로 연결 — 법 조항이 붙은 문서를 그대로 보낼 수 있다
  • 심사기간 한 달 내내 죽지 않는다 (가용성 > 기능)
  • 새 가격 도메인이 구조 변경 없이 꽂힌다

범위 제외 (Non-goals)

  • 판정·등급·추천을 하지 않는다 — 위치와 배수라는 사실만
  • 실시간 가격이 아니다 — 공시 주기(월·주간)의 재구성이며 기준 시점을 화면에 명시
  • 예약·결제·중개 기능 없음 — 정보와 문서까지가 범위
  • 세대·개인 맞춤 계산 아님 (반환 추정은 기준 면적 명시 후 예시로만)
  • 유치원·어린이집 원비 — 전국 데이터 부재 확인으로 탈락 (해결된 사항 #7)

05시나리오

Scenarios — 실제 사용 상황을 단계로.

심사위원 — 하루 50개 심사, 30초 판단

  1. 링크를 연다 → 로그인 없이 실단지 검진표가 이미 펼쳐져 있다 (송파 삼환가락 · 하위 1% · 주의)
  2. 자기 아파트 이름을 친다 → 진짜 나온다 (전국 21,165단지)
  3. "AI 질의서 만들기"를 누른다 → 법 조항·수치가 박힌 문서가 스트리밍으로 타이핑된다

이사 검토자 — "은마 살까?"

  1. 은마 검색 → 47년차 · 장충금 하위 16% 관찰 · 난방비 평균 1.5배 속도
  2. 분포 곡선에서 내 위치 점을 본다 → /method에서 계산식을 확인한다
  3. OG 카드로 배우자에게 공유한다

이사 나가는 세입자 — 몰랐던 돈

  1. 검진표 하단 "전세·월세로 살다 이사하셨나요?" 훅을 본다
  2. 대신 낸 장기수선충당금이 돌려받는 돈임을 알게 된다 (시행령 §31⑧)
  3. "반환 확인서 요청문"을 만들어 관리사무소에 보낸다

06다이어그램

Diagrams — 작성자는 직관으로 알지만, 검토자에게는 그림이 필요하다. 편집 가능한 소스 포함.

인터랙티브 뷰어 — 상단 뷰 탭(검진 경로 · 데이터 계보 · AI 경계 · 무결성 게이트)으로 관심 경로만 분리해 볼 수 있다. 전체 화면으로 열기 · 소스는 archify JSON(jegap5.architecture.json)으로 재현·수정 가능.

읽는 순서: 아래 행이 요청 경로(사용자 → UI → API → 엔진, 강조선), 위 행이 데이터 계보(5원천 → 인제스트 → 무결성 게이트 → 번들, 점선 = 주간 배치). 두 행이 만나는 지점은 단 하나 — 엔진이 번들을 모듈 캐시로 읽는 세로선이다. 런타임에 외부로 나가는 호출은 Claude 문장 다듬기(SSE) 하나뿐이다.

07용어집

Glossary — 이 문서와 제품이 쓰는 내부 용어.

장충금 (장기수선충당금)
배관·승강기 등 미래 대규모 수선을 위해 매달 적립하는 돈. 제품에서는 "미래 수리비 저금"으로 병기한다.
유사군
비교 대상 집단. 도메인마다 규칙이 다르다 — 관리비: 같은 시도×연식±5년×세대수 구간×난방 / 병원: 시도×종별 / 학원: 시군구×표준 과목.
완화 사다리
유사군 표본이 30개 미만이면 조건을 한 단계씩 넓히고, 넓혔다는 사실을 화면에 표기하는 규칙.
무소음 원칙
불확실하면 표시하지 않는다. 표본 부족·시계열 단절·공시 오류 의심 값은 결과 자체를 내리지 않는다.
검진표
결과 화면의 은유. 신호(양호·관찰·주의) + 백분위 + 종합 소견으로 구성 — 등급·판정이라는 말은 금지어다.
대필 (처방전)
검진 결과를 근거 법 조항이 붙은 실행 문서(질의서·확인 요청문 등)로 바꿔 주는 기능. 총 6종.

11인터페이스

Interfaces — 경계의 계약. 여기가 바뀌면 비싸다.

도메인 어댑터 계약

모든 가격 도메인은 두 계약 중 하나를 구현한다. 새 도메인 추가 = 인제스트 스크립트 + 설정 몇 줄.

  • DataSource (관리비) — search / get / all / worst / isSample. fixture와 실데이터가 같은 계약이라 데이터 없이도 앱이 완동한다.
  • makeDomain(config) (병원·학원·장례) — file, minPeers, peerKeys[](완화 사다리를 키 함수 배열로 선언) → ready / search / get / exams.

대필 API 계약

  • POST /api/{rx|arx|hrx|frx} → text/plain 스트리밍. 헤더 x-rx-mode: llm | template이 생성 방식을 정직하게 알린다.
  • 실패 계약: 첫 문장 전 실패 = 템플릿 폴백(200) / 도중 실패 = 부분 출력 + 중단 안내 / 잘못된 입력 = 400 / 남용 = 429.

URL 구조

/ 관리비 홈(워스트 사례) · /d/[code] 단지 · /h|/a|/f/[id] 병원·학원·장례 · /p/[시도] 지역 물가 · /method 산식 — 모든 상세는 OG 이미지 라우트를 동반한다.

13보안

Security — 위협 모델과 신뢰 경계. 설계 단계 항목이지만, 이 프로젝트에선 적대 감사로 사후 검증했다.

  • 공격 표면은 사실상 대필 라우트 4개뿐 — 로그인·DB·파일 업로드가 없다. 검색은 인메모리 includes라 주입 표면이 없다.
  • 과금 남용(익명 LLM 호출 루프)이 최대 위협 — IP 레이트리밋(분당 5회, 429)으로 차단. 남용 관찰 시 전역 저장소 기반 리밋으로 승격 예정.
  • 프롬프트 주입 — LLM 입력은 전부 정부 데이터셋 유래이고 사용자 입력은 조회 키로만 쓰인다. 적대 감사에서 주입 경로 미발견.
  • 입력 검증 — 4개 라우트 공통 파서: 깨진 JSON·잘못된 id·허용 외 kind는 400.
  • 신뢰 경계 — 공공데이터조차 신뢰하지 않는다: 무결성 게이트가 공시 오류(예: 소주 2,500만 원)를 이상치 규칙으로 걸러낸다.

14개인정보

Privacy

수집하는 개인정보가 없다. 로그인·회원가입 없음, 검색어 저장 없음, 쿠키·트래커 없음. 다루는 데이터는 전부 기관 단위의 정부 공개 정보다. 유일한 개인 연관 값(세입자 반환 추정액)은 서버로 전송되지 않는 화면 내 계산이며, 대필 문서의 동·호수는 사용자가 복사 후 직접 채우는 빈칸이다.

15법적 고려사항

Legal considerations — 이 제품에서 가장 두꺼운 섹션인 것이 맞다.

  • 사실적시 명예훼손(정보통신망법 §70①) — 실명 기관에 대한 위치 표시가 핵심 리스크. 방어 구조: 정부가 이미 실명 공개한 공시가의 재구성 + 판정어 금지(테스트로 강제) + 산식 전문 공개 + 무광고·비영리 + 24시간 정정 채널 → "비방 목적" 부정의 전형 요건. 홈의 실명 하이라이트는 의도된 리스크 감수로 결정(2026-09-16, 저자) — 항의 수신 시 정정 채널 우선 대응, 분쟁 격화 시 익명화 전환 지점을 코드에 기록해 둠.
  • 법 조항 인용 정확성 — 대필 문서가 인용하는 전 조항(관리비 §27③·§30·시행령 §31⑧⑨, 의료법 §45, 학원법 §15, 장사법 §29)을 국가법령정보센터 기준으로 검증 완료. 잘못된 조항 인용(§31⑩)을 적대 감사가 검출해 정정한 이력 있음.
  • 데이터 이용 조건 — 공공누리 1유형(장례), 심평원 비영리 조건, 공공데이터포털 개방 조건 각각 확인. 최신 데이터가 필요한 e하늘 화면 스크래핑은 법적 회색으로 판단해 배제하고 개방본(2023-06)을 기준 시점 명시로 사용.

16로깅

Logging — 무엇을 남기고, 무엇을 남기지 않는가.

Vercel 기본 함수 로그(요청 경로·상태·지연)만 사용한다. 애플리케이션 레벨에서 추가로 남기는 것은 없다 — 검색어·생성된 문서 내용·IP를 자체 저장하지 않는다(레이트리밋 버킷은 인메모리·휘발성). 데이터 갱신은 로그가 아니라 git 커밋이 감사 기록이다: 인제스트 산출물이 리포에 커밋되므로 "언제 어떤 데이터로 무엇이 보였는지"를 커밋 해시로 재현할 수 있다.

19검토된 대안

Alternatives considered — 간결하게, 왜 아닌지만.

Supabase + pg_trgm검색·조회는 훌륭하지만 심사기간의 외부 장애점이 된다. 데이터가 주간 정적이라 DB의 이점(쓰기·동시성)이 없었다.
recharts 등 차트 라이브러리번들 비대 + 어디서나 본 "AI 앱 룩". 분포·스파크는 서버 계산 인라인 SVG로 충분했다.
LLM이 소견 생성수치를 만들 위험. 소견은 결정론 템플릿, LLM은 문장 다듬기로 역할을 갈랐다 — "AI가 숫자를 만들지 않는다"가 오히려 차별화가 됐다.
API 증분 적재일 1,000콜 상한으로 초기 적재만 72일. 벌크 파일(주간) + 재배포가 더 단순하고 재현 가능.
도메인별 개별 구현병원 편에서 실제로 한 번 저질렀고(공용 컴포넌트 미적용), 그 결과가 소견 누락 버그였다. 공용 엔진 + 설정 선언이 정답.

20확장 전략 — 공시가 열릴 때마다 검진이 늘어난다

Future expansion — 이 설계의 가장 큰 자산은 특정 도메인이 아니라 흡수하는 레시피다.

정부는 계속해서 가격 공시를 연다 — 법이 게시를 강제하는 영역이 늘고, 닫혀 있던 데이터가 개방된다. 이 앱은 새 공시가 등장할 때마다 같은 커리큘럼으로 흡수하도록 설계됐다. 도메인 지식은 설정으로 격리되어 있고, 화면·엔진·대필·공유는 전부 공용이다.

흡수 레시피 — 4단계, 검증된 소요 반나절

  1. 원천 실증 — 데이터가 진짜 있는지 실호출·실파일로 확인한다 (추측 금지. 유치원 원비는 이 단계에서 탈락했다)
  2. 인제스트 스크립트 — 원천 → {도메인}.json.gz. 이상치·단절 규칙은 공용 게이트가 처리
  3. 어댑터 선언 — makeDomain({ file, minPeers, peerKeys }) 몇 줄. 유사군과 완화 사다리를 키 함수로 선언하면 위치·배수·소견·검색이 전부 따라온다
  4. 화면·대필 선언 — 공용 컴포넌트에 카피와 근거 법 조항만 주입. 탭·OG·/method 항목 추가

실증

이 레시피는 가설이 아니라 기록이다 — 4호 장례비편과 5호 생활물가편이 각각 반나절 만에 이 절차 그대로 올라갔고, 그중 3단계 이후는 코드 수십 줄이었다. 반대로 원비편은 1단계에서 정직하게 탈락했다 — 레시피에는 "안 되는 것을 빨리 아는 것"도 포함된다.

21질의와 답

설계 루프·심사 루프·교차 감사에서 실제로 받았던 질문과, 예상 질문.

Q1왜 등급이나 점수를 안 매기나? 사용자는 한 줄 결론을 원할 텐데.

두 가지 이유다. 법적으로 — 실명 기관에 대한 등급은 "비방 목적" 다툼의 정중앙이고, 위치·배수는 검증 가능한 사실이다. 제품적으로 — 등급은 근거가 감춰진 판단이고, "17곳 중 3번째로 높음"은 사용자가 스스로 판단하게 하는 데이터다. 신호(양호·관찰·주의)가 결론 요약의 역할을 대신하되, 그 경계값까지 /method에 공개해 판정이 아닌 규칙임을 보였다.

Q2AI 챔피언십인데 AI가 한 일이 "문장 다듬기"뿐이라 약하지 않나?

런타임 기능만 보면 그렇게 보이지만, 이 제품에서 AI의 자리는 세 층이다. ① 개발 전 과정이 AI 협업(아이디어 10라운드 → 설계 패널 → 자율 빌드 → 교차 감사 — AI_TOOLS.md에 전부 기재). ② 런타임에선 "AI가 숫자를 만들지 않는다"는 선언 자체가 설계다 — 검증 가능성이 신뢰 서비스의 조건이라서다(/method §0). ③ 대필 6종은 다듬기가 아니라 권리의 문서화다 — 검진 결과와 법 조항을 조립해 보내도 되는 문서로 바꾸는 것이 이 제품의 행동 루프다.

Q3공공데이터가 틀리면 어떡하나? 실제로 틀린 걸 봤나?

봤다 — 장례식장 공시에 "소주 25,001,800원", 조사 단위가 바뀌며 닭고기가 한 달 새 반토막. 그래서 무결성 게이트를 뒀다: 시계열 ±35% 점프는 그 이전과의 비교를 차단하고, 중간값의 50배 초과·저액 항목은 표시하지 않는다. 그래도 새는 건 24시간 정정 채널로 받는다. 원천 오류를 우리가 다 못 잡는다는 것을 전제한 설계다.

Q4아파트아이·참가격·하모니가 이미 있는데 뭐가 다른가?

기존 서비스는 숫자 표를 준다. JEGAP은 세 가지를 더한다 — ① 위치 번역("하위 7%", "중간값의 2.5배"), ② 행동 연결(법 조항 붙은 대필 문서), ③ 한곳 통합(물어볼 권리가 있는 가격 5종). 그리고 도메인 선정 원칙 자체가 차별화다: "불투명하고, 협상 불가하고, 물어볼 권리가 법에 있는 가격만" — 그래서 우유는 안 하고 장례비는 한다.

Q5DB 없이 데이터를 앱에 내장한 게 규모가 커지면 무너지지 않나?

맞다, 상한이 있다 — 그리고 그 상한이 명확하다는 게 이 선택의 장점이다. 현재 8.5MB, 도메인당 수 MB씩 늘어도 수십 개 도메인까지는 서버리스 번들 한도 안이다. 읽기 전용·주간 갱신 데이터에 DB를 두면 얻는 것은 없고 심사기간의 장애점만 는다. 무너지는 시점(수백 MB, 혹은 사용자 생성 데이터 등장)이 오면 그때 DataSource 계약 뒤에서 저장소만 갈아끼운다 — 그러라고 계약을 뒀다.

Q6명예훼손으로 신고당하면?

신고 자체는 누구나 할 수 있다 — 그것과 성립은 다른 문제다. 정부가 실명 공개한 공시가의 재구성 + 판정어 부재 + 공익 목적 정황(무광고·산식 공개·정정 채널)으로 "비방 목적" 부정 요건을 갖췄다. 실질 리스크는 패소가 아니라 대응 비용이며, 항의 수신 → 정정 채널 → (격화 시) 익명화 전환의 3단 대응을 준비해 뒀다. §15 참조.

Q7데이터 갱신을 잊으면 낡은 가격이 계속 보이는 것 아닌가?

그래서 모든 화면에 기준 시점을 박았다("2026.08 조사", "2023.6 공시분"). 낡음 자체보다 낡음을 숨기는 것이 신뢰를 깬다. 갱신은 인제스트 스크립트 재실행 + 재배포이며, 커밋이 갱신 이력이 된다.

Q8이 설계에서 다시 한다면 바꿀 것 하나는?

공용 가격 엔진(makeDomain)을 2호가 아니라 1호부터 깔았을 것이다. 관리비편이 전용 엔진으로 먼저 만들어진 탓에 지금 두 계약이 공존하고, 병원편 통합 누락 같은 이음새 버그가 거기서 나왔다. "확장은 나중에"가 아니라 확장 계약이 곧 1호의 스펙이어야 했다.
